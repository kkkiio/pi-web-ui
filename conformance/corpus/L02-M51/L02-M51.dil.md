## 真正有价值的区别：Ponte 可以借助你自己的代理节点建立远程连接

这是截图里推荐 Ponte 的人可能真正看重的功能。

Surge 官方明确支持 **通过代理进行 NAT 穿透**，可以利用支持 UDP 转发的 Shadowsocks、Trojan、SOCKS5 等代理。客户端也能配置代理路径，以改善某些网络环境下的连接。<Cite ref="turn101378view1"/>

对比如下：

| | Shadowrocket + Tailscale | Surge + Ponte |
|---|---|---|
| 代理与组网共用一个 App | ✅ | ✅ |
| 远程访问 Mac 的网页服务 | ✅ | ✅ |
| 依赖 Tailscale 控制服务 | 是 | 否 |
| 使用 Tailscale DERP | 可能 | 否 |
| 支持通过自选代理辅助穿透 | 取决于具体路由能力 | 官方明确支持 |
| Mac 必须安装 Surge | 不需要 | 需要 |
| 跨平台组网 | Tailscale 支持多平台 | Ponte 主要限于 Apple 生态 |

## 对你之前的问题，有没有实际帮助？

你之前强制使用 DERP，连接仍然很差。

**如果瓶颈确实是 DERP 中继线路，那么：**

- 换成 Shadowrocket 内置 Tailscale：主要解决两个 VPN 共存的问题，继续使用原来的 Tailscale 网络，**不保证改善 DERP 线路质量**。
- 换成 Surge Ponte：能使用另一套连接机制，并借助你已有的稳定代理节点，**有机会绕开之前表现很差的 DERP 路径**。

当然，Ponte 也不能保证一定更快。

## 我的建议

**如果你已经购买 Shadowrocket，就先别为了 Ponte 买 Surge。**

可以先试 Shadowrocket 新增的 Tailscale 功能。如果网页仍然经常加载失败，说明仅仅统一 VPN 接口可能不够，你更需要改变远程连接的传输路径。

另外，你的实际需求只是「在外面用 iPhone 访问 Mac 的 Web 服务」，未必需要完整的虚拟局域网。使用受身份验证保护的 HTTPS Tunnel，也可能比这两套方案更适合。

**一句话总结：Shadowrocket 已经解决了你说的「功能统一」；Ponte 真正值得关注的是「它提供了另一种远程连接和代理辅助穿透路径」，而不只是把 Tailscale 的功能重新做了一遍。**
