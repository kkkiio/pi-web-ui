## 一、在小米 Pad 8 Pro 上开启无线调试

小米官方给出了开启开发者选项的方法。具体菜单名称可能随澎湃 OS 版本略有变化。<Cite ref="turn477007search0"/>

<list marker="number" gap={2}>
  <list-item>打开 **设置 → 我的设备 / 关于平板 → 全部参数与信息**。</list-item>
  <list-item>连续点击 **澎湃 OS 版本**约 7 次，直到出现已经进入开发者模式的提示。</list-item>
  <list-item>返回 **设置 → 更多设置 → 开发者选项**。</list-item>
  <list-item>找到 **无线调试（Wireless debugging）**，打开开关并同意当前 Wi-Fi 网络的调试授权。</list-item>
  <list-item>点击 **使用配对码配对设备**，保持弹窗打开。</list-item>
</list>

此时 Pad 会显示 IP 地址、配对端口以及六位配对码。

整个过程无需连接 Mac 的 USB 线。<Cite ref="turn142576search5"/>

## 二、Mac 安装 ADB 并无线连接 Pad

ADB 是 Android 官方的调试工具，你不需要安装完整的 Android Studio。

如果 Mac 已安装 Homebrew，打开终端执行：

<CodeBlock language="bash">brew install --cask android-platform-tools

adb version</CodeBlock>

这是 Homebrew 当前支持的安装方式。<Cite ref="turn243440search0"/>

也可以从 <Link url="https://developer.android.com/tools/releases/platform-tools" title="Google 官方 SDK Platform-Tools 下载页面"/> 下载 Mac 版本。

随后在 Mac 终端执行配对命令：

<CodeBlock language="bash"># 示例地址，请替换为 Pad 配对窗口中显示的地址
adb pair 192.168.1.100:37123

# 按终端提示输入 Pad 显示的六位配对码
</CodeBlock>

配对成功后，回到 Pad 的「无线调试」主页。这里显示的**调试连接端口可能与刚刚的配对端口不同**。

例如主页显示 `192.168.1.100:38567`，就执行：

<CodeBlock language="bash">adb connect 192.168.1.100:38567

adb devices</CodeBlock>

如果输出类似：

```text
List of devices attached
192.168.1.100:38567    device
```

就证明 Mac 已经无线连接到 Pad。

有些设备配对后会自动连接，此时直接运行 `adb devices` 即可，不必再执行 `adb connect`。<Cite ref="turn513140view1"/>

## 三、让 Mac 的 Chrome 远程调试 Pad 的 Chrome

接下来是你最关心的环节。

先在 Pad 上打开 Chrome，随便访问一个网页，例如你的 MIDI 测试页面。

然后在 Mac 终端执行：

<CodeBlock language="bash">adb forward tcp:9222 localabstract:chrome_devtools_remote</CodeBlock>

这条命令会把 Pad 中 Chrome 的调试接口转发到 Mac 的本地 9222 端口。

随后在 Mac 的 Chrome 地址栏输入：

`chrome://inspect/#devices`

正常情况下，可以看到 Pad 的 Chrome 标签页，并点击 `inspect` 开始调试。Google 官方文档明确支持通过 Wi-Fi ADB 建立这种连接。<Cite ref="turn764459view0"/>

如果没有自动显示，可以访问 Mac 上的 `http://localhost:9222/json` 检查调试目标，或在 `chrome://inspect` 中启用 Discover network targets，将 `localhost:9222` 添加为目标。

<box background="surface-secondary" radius="lg" padding={3} gap={2}>
  **连接成功后，你可以直接在 Mac 的 DevTools Console 运行：**

  <CodeBlock language="javascript">console.log("Secure:", window.isSecureContext);

console.log(
  "Web MIDI:",
  typeof navigator.requestMIDIAccess
);</CodeBlock>

  理想输出：

  ```text
  Secure: true
  Web MIDI: function
  ```

  接下来点击 Pad 网页上的「连接 MIDI」按钮，Mac 的 Console 就可以实时显示你弹奏的 MIDI 事件。
</box>

## 四、还有一个特别适合你的功能：无线访问 Mac 本地开发服务器

这可能比单纯的远程 DevTools 更有价值。

假设你未来使用 React + Vite 开发钢琴教学软件，Mac 上启动：

<CodeBlock language="bash">npm run dev -- --port 5173 --strictPort</CodeBlock>

通常网页运行在：

`http://localhost:5173`

但这里有个细节：Pad 自己的 `localhost` 并不是 Mac 的 `localhost`。

好在 ADB 提供了一个非常有用的命令：

<CodeBlock language="bash">adb reverse tcp:5173 tcp:5173</CodeBlock>

它会把 **Pad 的本地 5173 端口映射到 Mac 的本地 5173 端口**。

因此你可以在 Pad 的 Chrome 中直接打开：

`http://localhost:5173`

实际看到的却是 Mac 上正在开发的网页！这也是 Android 官方推荐的本地开发服务器访问方式。<Cite ref="turn513140search0"/>

### 这个办法还有一个额外优势

Web MIDI API 要求页面在安全上下文（Secure Context）中运行。

通常直接从 Pad 访问 Mac 的局域网地址，例如 `http://192.168.1.20:5173`，并不满足这个要求。

但是 `http://localhost:5173` 被浏览器视作可信本地来源。

所以通过 `adb reverse`，你不仅能访问 Mac 的开发服务器，还可以在 Pad 上正常请求 Web MIDI 权限，前提是 Chrome 和系统具备相应的 MIDI 支持。<Cite refs={["turn489660search15","turn477007search8"]}/>

这对你的项目非常重要！

以后每次开发，你只需要确认无线 ADB 已连接，并运行这些命令：

<CodeBlock language="bash"># 检查无线连接
adb devices

# 让 Pad 访问 Mac 的 Vite 服务
adb reverse tcp:5173 tcp:5173

# 将 Pad 的 Chrome 调试接口转发到 Mac
adb forward tcp:9222 localabstract:chrome_devtools_remote</CodeBlock>

然后：

- Mac 运行 Vite 开发服务器。
- Pad Chrome 打开 `http://localhost:5173`。
- Mac Chrome 打开 `chrome://inspect/#devices` 进行调试。

Pad 的 USB-C 口全程可以连接电钢琴。

### 两点提醒

无线 ADB 一般要求 Mac 与 Pad 在同一 Wi-Fi 网络，而且网络不能开启客户端隔离。无线调试有时会在切换网络后断开，需要重新连接。<Cite ref="turn142576search2"/>

如果使用 DevTools 的 Screencast（屏幕投射），可能影响 Pad 的动画帧率。测试下落音符是否流畅时，最好关闭投屏，只保留必要的性能监控。<Cite ref="turn764459view0"/>

**我的建议：就使用「无线 ADB + adb reverse + Chrome DevTools」这套组合。** 对于你正在规划的网页版钢琴教学项目，这是一套不需要额外购买硬件、又能同时进行 USB MIDI 实机测试和网页热更新的开发方案。
