## 二、最基本的 HTTP 请求与响应

### 1. 请求格式

下面是一个可以直接运行的 cURL 示例：

<CodeBlock language="bash" editable>
curl https://api.anthropic.com/v1/messages \
  -H "Authorization: Bearer $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "system": "You are a helpful assistant.",
    "messages": [
      {
        "role": "user",
        "content": "Explain what an API is."
      }
    ]
  }'
</CodeBlock>

你会发现它与 Chat Completions 相当接近。

但注意几个地方：

**第一，Anthropic 有一个比较特别的 HTTP Header：**

```http
anthropic-version: 2023-06-01
```

这是 Anthropic 的 API 协议版本，不是模型版本，也不是指模型在 2023 年发布。

此外，Anthropic 目前支持 `Authorization: Bearer ...`，同时兼容 `x-api-key` 方式。官方 SDK 会自动处理这些请求头。<Cite refs={["turn602376view2","turn618649search1"]}/>

**第二，`max_tokens` 是请求中的必需字段。**

而 OpenAI Chat Completions 中的 `max_completion_tokens`、Responses 中的 `max_output_tokens`，在很多使用方式下可以省略。

**第三，`system` 放在顶层。**

OpenAI Chat Completions 的常见写法是：

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful assistant."
    },
    {
      "role": "user",
      "content": "Hello"
    }
  ]
}
```

Anthropic 的常见写法则是：

```json
{
  "system": "You are a helpful assistant.",
  "messages": [
    {
      "role": "user",
      "content": "Hello"
    }
  ]
}
```

这有点类似于 Responses API 将系统级指令提取为顶层 `instructions`。

补充一个较新的变化：部分新款 Claude 模型也支持在 `messages` 中间插入 `system` 角色消息，用于动态追加指令，但**对话开始时的系统指令仍应使用顶层 `system`**，并且中途插入有模型及位置限制。<Cite ref="turn251480view0"/>

### 2. 响应格式

一个简化的响应可能是：

<CodeBlock language="json">
{
  "id": "msg_01abc123",
  "type": "message",
  "role": "assistant",
  "model": "claude-sonnet-5-5",
  "content": [
    {
      "type": "text",
      "text": "An API is a way for software systems to communicate."
    }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 25,
    "output_tokens": 18
  }
}
</CodeBlock>

<caption>示意响应，省略部分可选字段；ID 和 Token 数仅用于说明结构。</caption>

对照 OpenAI，最重要的是你如何读取模型生成的文本：

<box border radius="lg" padding={3} gap={3}>
  <box gap={1}>
    <text color="secondary" weight="medium" size="xs">OpenAI Chat Completions</text>
    <row align="center" justify="between">
      <text weight="medium">`choices[0].message.content`</text>
      <badge color="secondary">string</badge>
    </row>
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <text color="secondary" weight="medium" size="xs">OpenAI Responses</text>
    <row align="center" justify="between">
      <text weight="medium">`output_text` （SDK 便捷属性）</text>
      <badge color="secondary">string</badge>
    </row>
    <text color="secondary" size="xs">底层需要遍历 `output[]` 中的消息与内容。</text>
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <text color="secondary" weight="medium" size="xs">Anthropic Messages</text>
    <row align="center" justify="between">
      <text weight="medium">`content[i].text`</text>
      <badge color="secondary">string</badge>
    </row>
    <text color="secondary" size="xs">先检查 `content[i].type == "text"`，而不是假设所有 Block 都是文本。</text>
  </box>
</box>

这就引出了 Anthropic 协议中最核心的设计：Content Blocks。

## 三、Content Blocks：Anthropic 最重要的抽象

OpenAI Chat Completions 主要围绕 Message 组织数据。

OpenAI Responses 则将 Message、Function Call、Reasoning 等放入类型化的 Items。

Anthropic 使用了介于两者之间的结构：

<box border radius="lg" padding={3} gap={2}>
  <box align="center" gap=1>
    <box background="surface-secondary" radius="md" padding={{x:4,y:2}}>
      **Message**
      <text size="xs" color="secondary" textAlign="center">role: assistant</text>
    </box>
    <icon name="arrow-down" color="tertiary"/>
    <box border radius="md" width="100%" padding={2} gap={2}>
      <text textAlign="center" weight="medium">`content[]`</text>
      <grid columns={3} gap={2}>
        <grid-item>
          <box background="surface-secondary" radius="md" padding={2} align="center" gap={1}>
            <icon name="file-text" color="secondary"/>
            <text weight="medium" size="xs">text</text>
          </box>
        </grid-item>
        <grid-item>
          <box background="surface-secondary" radius="md" padding={2} align="center" gap={1}>
            <icon name="wrench" color="secondary"/>
            <text weight="medium" size="xs">tool_use</text>
          </box>
        </grid-item>
        <grid-item>
          <box background="surface-secondary" radius="md" padding={2} align="center" gap={1}>
            <icon name="brain" color="secondary"/>
            <text weight="medium" size="xs">thinking</text>
          </box>
        </grid-item>
      </grid>
    </box>
  </box>
</box>

例如，Claude 可能在同一个 assistant Message 中同时返回文字和工具调用：

<CodeBlock language="json">
{
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "I'll check the weather."
    },
    {
      "type": "tool_use",
      "id": "toolu_123",
      "name": "get_weather",
      "input": {
        "city": "San Francisco"
      }
    }
  ],
  "stop_reason": "tool_use"
}
</CodeBlock>

在 OpenAI Chat Completions 中，这两部分通常对应：

- `message.content`
- `message.tool_calls`

在 OpenAI Responses 中，文字 Message 和 `function_call` 通常是 `output[]` 内不同类型的 Item。

而 Anthropic 将它们统一放进同一个 Message 的 `content[]` 里。

因此可以把两种模型抽象成：

```text
OpenAI Responses:
Response
  └── output[]
       ├── message
       │    └── content[]
       ├── function_call
       └── reasoning

Anthropic Messages:
Message
  └── content[]
       ├── text
       ├── tool_use
       └── thinking
```

请注意，这是为了理解结构而做的简化图，不代表它们支持的所有类型。

**对于构建统一 LLM SDK 的开发者，这个区别很重要：两个 API 都能表达工具调用，但结构化事件所在的层级不一样。**

输入端同样可以使用 Content Blocks。例如，给 Claude 发送图片时，`user.content` 可以包含 `image` Block 和 `text` Block：

```json
{
  "role": "user",
  "content": [
    {
      "type": "image",
      "source": {
        "type": "url",
        "url": "https://example.com/photo.png"
      }
    },
    {
      "type": "text",
      "text": "What is in this image?"
    }
  ]
}
```

这种设计也可以扩展到文档、搜索结果等不同类型的输入。<Cite refs={["turn618649search1","turn251480view1"]}/>

## 四、多轮对话：更像 Chat Completions，而不是有状态的 Responses

这个区别对后端开发特别重要。

**Anthropic Messages API 默认是 Stateless（无状态）的。**

意思是说，你发送一次消息，拿到模型结果，下一次请求并不能仅仅提供上一次返回的 `msg_id`，就让模型自动知道历史对话。

你需要把历史消息重新提交。

例如：

<CodeBlock language="python" editable>
import anthropic

client = anthropic.Anthropic()
model = "claude-sonnet-5-5"

messages = [
    {"role": "user", "content": "My name is Alice."}
]

# 第一轮
r1 = client.messages.create(
    model=model,
    max_tokens=1024,
    messages=messages,
)

# 保留完整的 assistant content
messages.append({
    "role": "assistant",
    "content": r1.content
})

# 第二轮
messages.append({
    "role": "user",
    "content": "What is my name?"
})

r2 = client.messages.create(
    model=model,
    max_tokens=1024,
    messages=messages,
)

print(r2.content)
</CodeBlock>

这里的 `msg_id` 只是响应标识，不等价于 OpenAI Responses API 的 `previous_response_id`。

<row gap={2} align="start">
  <icon name="lightbulb" color="secondary" size="lg"/>
  <box flex="1" gap={1}>
    **关键理解**

    Anthropic Messages 的核心思路是：**模型计算一条新消息，客户端负责准备它所需要的上下文。**

    而 OpenAI Responses API 既支持客户端手动传入完整历史，也支持通过 `previous_response_id` 或 Conversations API 关联服务端保存的上下文。<Cite refs={["turn251480view0","turn528979view3"]}/>
  </box>
</row>

Anthropic 另外提供 Managed Agents 和 Sessions 等机制，但它们属于另一层产品能力，不应与基本的无状态 Messages 协议混为一谈。
