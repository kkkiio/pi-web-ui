# Anthropic Messages API 完整解析：与 OpenAI API 对比

如果你已经了解 OpenAI 的 Chat Completions API 和 Responses API，那么理解 Anthropic 的 API 会相当容易，因为它们在设计理念上有很多共通之处。

**先给你一个核心结论：**

> Anthropic 的 **Messages API**，可以理解成采用了类似 OpenAI Chat Completions 的对话输入形式，但使用了结构化 Content Blocks 来表达文本、工具调用、推理和多模态内容。
>
> 从数据结构上看，它有些地方又很像 OpenAI Responses API，只不过它的对话状态管理更接近传统的 Chat Completions API。

Anthropic 主要通过一个模型生成接口提供 Claude 的对话和生成能力：

```http
POST https://api.anthropic.com/v1/messages
```

它既可以完成简单的文本生成，也可以支持多轮对话、Tool Calling、Streaming、Extended Thinking、多模态输入以及结构化输出。<Cite refs={["turn618649search1","turn618649search2"]}/>

## 一、先建立整体映射关系

| 对比维度 | OpenAI Chat Completions | OpenAI Responses | Anthropic Messages |
|---|---|---|---|
| 生成接口 | `/v1/chat/completions` | `/v1/responses` | `/v1/messages` |
| 对话输入 | `messages` | `input` | `messages` |
| 系统指令 | `messages` 中的 `system` / `developer` | `instructions` 或输入中的指令消息 | 顶层 `system` |
| 生成长度 | `max_completion_tokens` | `max_output_tokens` | `max_tokens` |
| 返回内容 | `choices[].message` | `output[]` | `content[]` |
| 内容表示 | 消息 + 内容 / 工具调用 | 类型化 Output Items | 类型化 Content Blocks |
| 工具调用 | `tool_calls` | `function_call` 等 Output Items | `tool_use` Block |
| 工具结果 | `tool` 角色消息 | `function_call_output` | `user` 消息中的 `tool_result` |
| 结束原因 | `finish_reason` | `status` 等状态信息 | `stop_reason` |
| 对话状态 | 通常由客户端管理 | 可通过服务端响应 ID 关联 | 通常由客户端管理 |
| 流式输出 | SSE | SSE | SSE |
