**ETag（Entity Tag）可以理解成 HTTP 资源的版本指纹，但不一定是内容哈希。**

它主要用来判断：**一个资源从上次读取后，有没有发生变化。**

例如服务器返回：

```http
HTTP/1.1 200 OK
ETag: "abc123"
```

客户端下一次修改资源时，可以带上：

```http
PUT /owner.json
If-Match: "abc123"
```

含义是：

> 只有当服务器当前的 ETag 仍然是 `"abc123"` 时，才允许这次修改。

否则服务器会返回 `412 Precondition Failed`。

这就是前面说的 CAS（Compare-and-Swap）可以利用的机制。

## ETag 到底是不是内容哈希？

**取决于具体实现。**

- **HTTP 标准：** ETag 是一个不透明标识符（opaque identifier），不规定必须采用什么算法。
- **Amazon S3：** 在某些简单上传场景下，ETag 是对象内容的 MD5；但分段上传等情况下，它通常不是整个对象的 MD5。
- **其他服务：** 也可能使用内部版本号或其他标识算法。

所以 ETag 最重要的语义不是“内容的哈希”，而是“用来验证资源表示是否仍然匹配”。
