你现在问到了理解 Linux 网络协议栈最关键的地方。

而且我觉得你之所以之前学 `iptables` 和 `conntrack` 总觉得混乱，很可能是因为很多教程把 **路由、Netfilter、iptables、conntrack** 放在一起讲，却没有区分：

- 哪些是内核真正执行数据包处理的机制？
- 哪些只是配置这些机制的规则？
- 哪些是内核为数据包维护的状态？

你的思路很接近了，但有一个地方需要纠正：

**Linux 网络协议栈并不是简单的「Hook → 策略规则 → 路由表」三层结构。**

更准确地说：

> 路由是内核决定数据包去向的机制；Netfilter Hook 是内核网络处理流程中的可扩展执行点；iptables/nftables 是配置数据包处理规则的机制；conntrack 则负责维护网络流的状态。

它们在同一个数据包处理流程中协作，而不是彼此上下叠加。

我们先解决 `dev`，然后构建一张完整的架构图。

## 一、`dev` 是什么意思？

`dev` 就是 **device（设备）** 的缩写。

例如：

```bash
ip route add 10.0.0.0/8 via 192.168.1.1 dev eth0
```

这里有三个部分：

| 字段 | 含义 |
|---|---|
| `10.0.0.0/8` | 目标网络前缀 |
| `via 192.168.1.1` | 下一跳 IP 地址 |
| `dev eth0` | 出口网络接口 |

你可以把 `dev` 理解为一个命令语法关键字。

类似：

```text
via = 通过哪个下一跳
dev = 使用哪个网络接口
```

它的作用主要是让 `ip` 命令的语法明确，而不是某种特殊的网络协议标志。

内核内部并不是保存一段 `dev eth0` 字符串，而是使用对应的网络设备对象、接口索引及相关路由信息。

还有一个小细节：

`dev` 后面不一定是物理网卡，也可以是：

- `eth0`：以太网接口
- `wlan0`：无线网络接口
- `tun0`：虚拟隧道接口
- `veth0`：虚拟以太网接口
- `wg0`：WireGuard 接口

所以比起“网卡”，以后我们最好统一使用 **网络接口（Network Interface）** 这个概念。

## 二、路由表不是所有机制的底层

我们先把主要概念分清。

| 名称 | 本质 | 核心职责 |
|---|---|---|
| Routing Table | 路由数据结构 | 决定发往哪里、从哪个接口出去 |
| Policy Routing (`ip rule`) | 路由选择规则 | 决定查哪张路由表 |
| Netfilter Hook | 内核执行点 | 在网络处理流程的特定位置执行回调 |
| iptables / nftables | 包过滤与处理规则系统 | 匹配数据包，执行放行、丢弃、NAT 等操作 |
| conntrack | 有状态连接跟踪系统 | 记录并识别网络流及其状态 |

这里我特意加入了 `ip rule`，因为它和 `iptables rule` 是两种完全不同的规则，非常容易混淆。

**`ip rule` 管的是怎么选择路由；`iptables` / `nftables` 的规则管的是怎么处理数据包。**

后面会看到，Netfilter 规则还能影响路由决策，例如修改目标 IP 或数据包的 mark。
