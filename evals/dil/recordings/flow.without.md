# pi-web-ui 发送事件全链路（跨进程流转图）

下面用**分层 ASCII 图**展示一次「点击发送」的完整往返，重点标出**进程边界**。

## 一、总览：一次往返跨越 3 个进程 + 2 个传输边界

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  [进程 A] 浏览器 / pi-web-ui (前端)                                          │
│                                                                              │
│   ① 用户点击 "发送" 按钮                                                     │
│        │                                                                     │
│   ② UI 组件收集输入 (text/attachments)  ──► 构造请求 payload               │
│        │                                                                     │
│   ③ 调用 client API (fetch / WebSocket send)                                │
│        │                                                                     │
└────────┼─────────────────────────────────────────────────────────────────────┘
         │
         │  ════════ 边界 ①: HTTP(S) / WebSocket  ════════
         │  （浏览器 ↔ Node 服务，跨网络栈 / 跨进程）
         │
┌────────▼─────────────────────────────────────────────────────────────────────┐
│  [进程 B] Node 服务：mirror-server.ts                                        │
│                                                                              │
│   ④ 路由匹配 (POST /message 或 ws 'message' 事件)                           │
│        │                                                                     │
│   ⑤ 鉴权 / 会话校验 / payload 解析                                           │
│        │                                                                     │
│   ⑥ 封装为 Pi 协议消息，定位目标 Pi 会话 / 实例                              │
│        │                                                                     │
│   ⑦ 写入与 Pi 进程的连接（stdin / socket / IPC）                            │
│        │                                                                     │
└────────┼─────────────────────────────────────────────────────────────────────┘
         │
         │  ════════ 边界 ②: 子进程 IPC / stdio / Unix Socket ════════
         │  （Node 主进程 ↔ Pi 子进程，跨 OS 进程）
         │
┌────────▼─────────────────────────────────────────────────────────────────────┐
│  [进程 C] Pi 进程（agent 核心）                                              │
│                                                                              │
│   ⑧ 反序列化输入 → 进入 agent loop                                           │
│   ⑨ 调用 LLM / 工具，产生流式 token / 事件                                   │
│   ⑩ 将结果按协议写回 stdout / socket                                         │
│        │                                                                     │
└────────┼─────────────────────────────────────────────────────────────────────┘
         │
         │  ◄════════ 返回路径（逆向穿越同样的边界）════════
         │
┌────────▼─────────────────────────────────────────────────────────────────────┐
│  [进程 B] mirror-server.ts                                                   │
│  ⑪ 读取 Pi 输出 → 解析事件 (token / tool_call / done / error)               │
│  ⑫ 转发到浏览器连接：SSE / WebSocket push / 长轮询响应                       │
└────────┼─────────────────────────────────────────────────────────────────────┘
         │
         │  ════════ 边界 ①（回程）════════
         │
┌────────▼─────────────────────────────────────────────────────────────────────┐
│  [进程 A] 浏览器 / pi-web-ui                                                 │
│  ⑬ 接收流式事件 → 更新 store / 渲染消息气泡                                  │
│  ⑭ 收到 done/error → 结束 loading 状态                                       │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 二、紧凑「跨边界」视图（一眼看清跳了几次）

```
 浏览器                 mirror-server.ts            Pi 进程
 (进程 A)                 (进程 B)                  (进程 C)
    │                        │                         │
    │──①点击发送────────────►│                         │
    │                        │                         │
    │        [边界① HTTP/WS] │                         │
    │                        │──②转发到 Pi────────────►│
    │                        │                         │
    │                        │      [边界② IPC/stdio]  │
    │                        │                         │
    │                        │◄──③流式事件─────────────│
    │                        │                         │
    │◄──④SSE/WS 推送─────────│                         │
    │                        │                         │
    │  [边界① 回程]          │                         │
    ▼                        ▼                         ▼
  渲染                    转发/编排                agent loop
```

**共跨越 2 类进程边界，往返各 1 次 → 总计 4 次边界穿越。**

## 三、每条链路对应的「边界类型」速查表

| 阶段 | 所在进程 | 跨越边界 | 传输形式 |
|------|----------|----------|----------|
| ① 点击发送 | 浏览器 | — | 用户事件 |
| ② 构造 payload | 浏览器 | — | 内存 |
| ③ client 请求 | 浏览器 | **边界①** | HTTP POST / WebSocket frame |
| ④ 路由匹配 | mirror-server | — | Node 事件循环 |
| ⑤ 解析/鉴权 | mirror-server | — | 内存 |
| ⑥ 封装协议 | mirror-server | — | 内存 |
| ⑦ 写 Pi 连接 | mirror-server | **边界②** | stdin / Unix socket / IPC |
| ⑧ agent loop | Pi | — | 进程内 |
| ⑨ 调用 LLM/工具 | Pi | （外部）| HTTP 到模型 API |
| ⑩ 写回结果 | Pi | **边界②** | stdout / socket |
| ⑪ 解析事件 | mirror-server | — | 流式解析 |
| ⑫ 推送浏览器 | mirror-server | **边界①** | SSE / WS push |
| ⑬ 更新 UI | 浏览器 | — | 渲染 |
| ⑭ 收尾 | 浏览器 | — | 状态机 |

## 四、关键洞察

1. **mirror-server.ts 是「双面胶」**：对上是 Web 服务器（HTTP/WS），对下是 Pi 的 IPC 客户端。它是唯一同时接触两个边界的进程。
2. **边界① 是「请求-响应 + 流式推送」混合**：发送走 POST/WS send，返回走 SSE/WS push —— 不是同一根管道，这是理解回程的关键。
3. **边界② 是长连接**：Pi 进程通常常驻，mirror-server 通过持久 stdin/socket 与其对话，事件是**流式**回灌的。
4. **回程不重新走边界①的请求**：浏览器收到的是 server 主动 push 的流，而不是原 fetch 的响应体（除非用长轮询）。这决定了前端的接收端必须是一个**订阅者**而非**等待者**。

> 说明：上图为基于 pi-web-ui / mirror-server 典型架构的**结构化抽象**。若你的代码里具体用的是 stdio 还是 Unix socket、SSE 还是 WS，可把「边界②/边界①」的标签替换为实际实现——但**进程拓扑和穿越次数不变**。
